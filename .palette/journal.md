## 2024-05-20 - [Explicit Focus for Gamepad Accessibility on Main Menus]
**Learning:** Godot Control nodes do not automatically grant focus to UI elements on scene load. This leaves gamepad users stranded on Main Menus until they explicitly click with a mouse. The Quit button signal was also misaligned between the .cs code and .tscn file (`_on_quit_game_btn_pressed` vs `_on_quitgame_btn_pressed`).
**Action:** Always map focus neighbors (`FocusNeighborTop` / `Bottom`) to create a wrap-around effect, explicitly call `GrabFocus()` on the default button during `_Ready()`, and use `MouseEntered += () => btn.GrabFocus();` so mouse movement syncs gracefully with gamepad focus selection. Ensure method signatures match the signal connections defined in `.tscn` files.

## 2024-05-21 - [Resource Inventory Updates Feel Static]
**Learning:** In Godot Control nodes, when numeric values in the inventory (like resource amounts) change rapidly, the instantaneous update feels disconnected. Creating dynamic `Tween` animations on `Label` properties (like scale and modulate) adds necessary juice and immediately draws the player's attention to state changes. It is crucial to kill existing tweens before creating new ones (`_currentTween?.Kill()`) to avoid visual glitching or memory leaks if the value changes rapidly before the previous animation completes.
**Action:** When updating numeric or state-based HUD elements, always implement a minor fallback checking mechanism for previous state (`_lastAmount`) and use a controlled, parallel `CreateTween()` sequence for scale and color shifting to highlight the change cleanly.
